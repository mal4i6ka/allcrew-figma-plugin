# AllCrew Figma Workspace — установка плагина

Готовый к запуску Figma-плагин. Собран заранее — билд не нужен, достаточно
импортировать манифест.

Плагин делает три разные вещи, и первая из них — не единственная:

1. **Экспорт пакета.** Переменные файла (design tokens) → CSS / JSON / TypeScript,
   с темами; по желанию — iOS-каталог (`Assets.xcassets`), `res/values{,-night}/colors.xml`,
   `Tokens.swift` и `Tokens.kt`. Дальше — целый сайт на Django + Bootstrap, React + CSS
   Modules с Code Connect или приложение Tauri: что собирать, решает пресет в настройках.
2. **Codegen в Dev Mode.** Панель кода Figma показывает тот же React, который
   лежит в экспорте, — разработчик читает ровно то, что уедет в репозиторий.
3. **Агентский канал.** Плагин слушает локальный мост, и терминальный агент
   (Claude Code, Codex, Cursor, обычный `curl`) читает и пишет файл Figma
   операциями, а не догадками: дерево экрана, токены за каждым значением, состояния
   компонентов, прототип, ассеты. Включается в **Settings → Agent listener**;
   чтения и записи разрешаются отдельными переключателями.

## Содержимое архива

```
manifest.json       — манифест development plugin
dist/code.js        — собранный main thread
dist/ui.html        — собранный UI
tools/bridge.mjs    — локальный Agent bridge
tools/mcp.mjs       — MCP front для bridge
tools/receiver.mjs  — необязательный Delivery receiver
README.md           — эта инструкция
LICENSE             — MIT
PRIVACY.md          — обработка данных
SECURITY.md         — trust model и security reporting
CHANGELOG.md        — изменения по версиям
```

Не перемещай `manifest.json` относительно папки `dist/`: Figma разрешает `main` и
`ui` относительно расположения манифеста.

## Установка — для человека

1. Распакуй архив в любую папку на диске (важно сохранить структуру —
   `manifest.json` и `dist/` должны лежать рядом).
2. Открой **Figma Desktop** (в браузерной версии импорт по манифесту
   недоступен).
3. Меню **Menu → Plugins → Development → Import plugin from manifest…**
   (если пункта «Development» нет — включи Developer mode в настройках
   аккаунта Figma).
4. Выбери файл `manifest.json` из распакованной папки.
5. Плагин появится в **Plugins → Development → AllCrew Figma Workspace**.
6. Открой Figma-файл с нужными переменными/коллекциями и запусти плагин —
   он сразу сканирует документ и показывает сводку. Настройки экспорта —
   через шестерёнку в шапке плагина.

Билд не требуется: `dist/code.js` и `dist/ui.html` уже собраны и готовы
к работе как есть.

## Обновления

В **Settings → Updates** всегда доступна ручная кнопка **Check now**. Автоматический
поиск релизов выключен по умолчанию; если включить его вручную, плагин обращается
к публичному GitHub Releases API не чаще одного раза в 24 часа. При наличии новой
версии в шапке появляется компактная панель с переходом к релизу и прямой загрузкой
архива. Development-плагин не может заменить собственные файлы: после загрузки
нужно заменить распакованную папку и заново открыть плагин в Figma.

### Размер панели

Потяни угол внизу справа, чтобы изменить окно плагина. Допустимый диапазон:
340×320…1400×1600. Двойной клик по ручке подгоняет высоту под открытую страницу,
не меняя ширину. Размер сохраняется глобально на этой машине через
`figma.clientStorage` и восстанавливается при следующем запуске. После 560 px
вёрстка переходит в широкий режим, а длинные таблицы и блоки кода растут вместе
с реальной высотой окна. В браузерном зеркале ручки нет: там раскладка следует
за размером окна браузера.

## Агентский канал: три шага

Нужен, только если файл будет читать агент. Плагин без него работает как
обычный экспортёр.

1. Запусти мост из распакованного архива:
   ```bash
   node tools/bridge.mjs
   ```
   Он слушает только loopback (`127.0.0.1:8788`) и ничего не публикует наружу.
2. Первый запуск создаёт секрет и открывает пятиминутное окно pairing. В плагине
   выбери **Agent Listener → Pair with bridge**.
3. Включи **Allow reads** и, только когда агент должен менять файл, **Allow writes**.

Development plugin не получает стабильный `figma.fileKey`, поэтому разрешения не
переносятся между запусками панели и не восстанавливаются по имени файла. После
перезапуска включи нужные gates заново.

Для MCP-клиента:

```bash
node tools/mcp.mjs --install claude
# также поддерживаются cursor, windsurf и vscode
```

С закрытым плагином часть чтений отвечает через REST API Figma: назови файл
(`fileKey` или переменная `ALLCREW_CHANNEL_FIGMA_FILE_KEY`) и положи токен в
`~/.allcrew-channel/figma-token`. Такие ответы помечены `source: "rest"`, и канал прямо
говорит, чего в них нет.

Полная документация канала — `agent/README.md` в репозитории плагина;
`GET /ops` у запущенного моста перечисляет операции с параметрами.

## Установка — для агента

Финальный шаг (импорт манифеста) — действие в GUI Figma Desktop: программного
API для установки dev-плагина у Figma нет. Агент готовит и проверяет пакет,
человек нажимает кнопку.

1. Распаковать архив:
   ```bash
   unzip allcrew-figma-workspace-v*.zip -d ~/figma-plugins/allcrew-figma-workspace
   ```
2. Проверить целостность пакета перед тем, как просить человека его
   импортировать:
   ```bash
   cd ~/figma-plugins/allcrew-figma-workspace
   test -f manifest.json && test -f dist/code.js && test -f dist/ui.html && echo OK
   python3 -c "import json; m=json.load(open('manifest.json')); \
     assert m['main']=='dist/code.js' and m['ui']=='dist/ui.html'; print('manifest OK')"
   ```
3. Сообщить человеку абсолютный путь к `manifest.json` и попросить выполнить
   шаги 3–5 из раздела «для человека».

Пересобрать из исходников (если есть чекаут репозитория, а не только архив):

```bash
npm install
npm run build     # обновляет dist/code.js и dist/ui.html
npm run package   # пересобирает этот архив целиком
```

Основная функция плагина сети не требует: переменные читаются через Figma
Plugin API на стороне клиента. Сеть нужна двум необязательным вещам — доставке
собранного пакета на настраиваемый receiver-эндпоинт и агентскому мосту на
петле.
